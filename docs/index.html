¿Qué es y para qué sirve?

El conector TheHive permite que el agente de Ruvic gestione casos e incidentes de seguridad directamente en tu instancia de TheHive (API v1). A diferencia de los conectores de solo consulta, este conector escribe: crea casos, agrega tareas, actualiza estados y agrega observables (IOC) reales. Una vez configurado, puedes pedirle al agente cosas como:

  • "Crea un caso de phishing reportado por finanzas y agrégale una tarea para analizar las cabeceras del correo."
  • "Marca el caso ~12345 como InProgress y agrega la IP 45.33.22.11 como observable."
  • "Actualiza a TruePositive el caso que abrimos ayer sobre el enlace malicioso."

Operaciones soportadas:

Operación Qué hace
security.create_case Crea un nuevo caso (título, descripción, severidad, TLP, etiquetas) y retorna su identificador
security.add_task Agrega una tarea de seguimiento a un caso existente
security.update_case_status Actualiza el estado de un caso (New, InProgress, Indeterminate, FalsePositive, TruePositive, Other)
security.add_observable Agrega un observable / indicador de compromiso (IP, dominio, hash, correo, URL, etc.) a un caso
Este conector escribe datos reales Crea y modifica casos, tareas y observables en tu plataforma de gestión de incidentes. No es de solo lectura: confirma con el equipo de seguridad antes de automatizar acciones que no hayan sido solicitadas explícitamente.

Prerrequisitos

  • Una instancia de TheHive (API v1) accesible por red desde la plataforma Ruvic, con una organización ya creada.
  • Acceso administrativo a esa organización en TheHive (para crear un usuario de servicio y asignarle un perfil), solo durante la configuración inicial.
  • Acceso de red desde Ruvic al host de TheHive (URL base alcanzable; regla de firewall si aplica).
  • Los datos de conexión que obtendrás en la sección siguiente: URL base y API Key del usuario de servicio.

Configuración en el fabricante

Vas a crear un usuario de servicio dedicado en TheHive, con un perfil limitado a la gestión de casos. No reutilices la API Key de tu cuenta de administrador: una API Key dedicada permite auditar la actividad del agente y revocarla sin afectar a otros usuarios.

  1. Crea (o identifica) la organización de trabajo en TheHive.

    Entra a TheHive como administrador y confirma la organización dentro de la cual el agente va a crear casos (por ejemplo, "Security Operations"). Todas las operaciones del conector ocurren dentro de una única organización.

  2. Crea un perfil (profile) de mínimo privilegio.

    En Organisation → Profiles, crea (o reutiliza) un perfil que otorgue únicamente manageCase, manageTask y manageObservable. No incluyas manageOrganisation, manageUser ni manageConfig: el conector no administra la plataforma.

  3. Crea el usuario de servicio para Ruvic.

    En Organisation → Users, crea un usuario dedicado (ej. ruvic-service) y asígnale el perfil de mínimo privilegio del paso anterior dentro de la organización correspondiente.

  4. Genera una API Key dedicada.

    Inicia sesión como ese usuario de servicio (o pide al administrador que la genere en su nombre): icono de usuario → My profile → API Key → Create. Copia la API Key inmediatamente: TheHive no vuelve a mostrarla completa. No uses la API Key de un usuario administrador ni la de tu cuenta personal.

    [ Captura: pantalla "My profile → API Key" en TheHive — reemplazar por assets/img/thehive-apikey.png ]
  5. Habilita el acceso de red desde Ruvic.

    Si tu instancia de TheHive restringe conexiones por IP (habitual en producción), permite la IP de la plataforma Ruvic en el firewall, security group o proxy inverso que protege la instancia.

  6. Anota los valores para la siguiente sección.

    Guarda la URL base de tu instancia (ej. https://thehive.empresa.com) y la API Key generada: los usarás en el formulario de configuración de Ruvic.

Permisos requeridos

Principio de mínimo privilegio: el usuario de servicio solo necesita estos permisos dentro de la organización configurada. No otorgues permisos de administración de la plataforma (gestión de usuarios, organizaciones o configuración global).

Permiso Para qué lo usa el conector
manageCase Crear casos (security.create_case) y actualizar su estado (security.update_case_status)
manageTask Agregar tareas de seguimiento a un caso (security.add_task)
manageObservable Agregar observables / indicadores de compromiso a un caso (security.add_observable)
Sin permisos de administración El conector nunca necesita manageOrganisation, manageUser ni manageConfig. Si el perfil del usuario de servicio incluye alguno de estos, retíralo.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta TheHive y pulsa Configurar. Diligencia el formulario con los valores obtenidos en la sección anterior:

Campo del formulario Valor
URL base de TheHive La URL de tu instancia, sin ruta ni barra final (ej. https://thehive.empresa.com)
API Key La API Key del usuario de servicio generada en el paso 4. Se guarda cifrada como secreto: la interfaz no volverá a mostrarla completa
Timeout de conexión (segundos) Opcional; 15 segundos por defecto

Guardar y luego pulsa Probar conexión — la plataforma se conectará a tu instancia de TheHive y confirmará que la API Key y la red funcionan.

[ Captura: formulario del conector TheHive en Settings → Conectores — reemplazar por assets/img/thehive-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: "Conexión exitosa a TheHive (https://tu-instancia)". La tarjeta del conector cambia a estado Configurado.

  2. Prueba mínima con el agente.

    Abre una conversación nueva con el agente y pídele, en un entorno de pruebas:

    "Crea un caso de prueba en TheHive titulado 'Prueba de conector Ruvic', severidad baja, y confírmame el id que devuelve."

    El agente debe confirmar el _id del caso creado. Verifícalo también en la interfaz web de TheHive. Si aparece, el conector quedó operativo de punta a punta.

Solución de problemas

Mensaje / síntoma Causa probable y solución
"Autenticación fallida: Credenciales inválidas o sin permiso suficiente para esta operación" La API Key es incorrecta, fue revocada, o el usuario de servicio no tiene el perfil con manageCase/manageTask/manageObservable. Genera una nueva API Key (paso 4 de la sección de fabricante) y vuelve a guardar el formulario.
"Error de red: No se pudo alcanzar TheHive en '...'" La plataforma Ruvic no alcanza la URL base configurada. Revisa que la URL no tenga errores de escritura, que no sea localhost (debe ser accesible desde Ruvic) y que el firewall permita la IP de Ruvic. Aumenta el timeout si la instancia responde lento.
El agente crea el caso pero falla al agregar tareas u observables ("403") El perfil del usuario de servicio no incluye manageTask o manageObservable, o el usuario pertenece a otra organización. Revisa el perfil asignado en Organisation → Users y ajústalo (paso 2 y 3 de la sección de fabricante).
"Error de datos: status '...' inválido. Valores permitidos: [...]" Se intentó actualizar un caso a un estado no soportado por TheHive. Los valores válidos son New, InProgress, Indeterminate, FalsePositive, TruePositive y Other (sensible a mayúsculas).
El conector aparece "Sin configurar" tras guardar La URL base o la API Key quedaron vacías (son obligatorias). Ábrelo de nuevo y completa ambos campos; el timeout es opcional.

Preguntas frecuentes y notas de seguridad

¿Puede el agente borrar casos o hacer cambios masivos?

No. El conector solo expone crear un caso, agregar una tarea, actualizar el estado de un caso y agregar un observable. No incluye operaciones de borrado ni de administración de la organización, ni aunque el perfil de TheHive lo permitiera.

¿Dónde queda guardada la API Key?

Como secreto en el almacén de credenciales de la plataforma Ruvic, asociado a tu organización. La interfaz nunca vuelve a mostrarla completa; solo indica "definida". Para cambiarla, escribe una nueva en el formulario; para conservarla al editar otros campos, deja el campo vacío.

Rotación de la API Key

Recomendado cada 90 días o según tu política de seguridad: genera una nueva API Key desde el perfil del usuario de servicio en TheHive, actualízala en el formulario del conector y pulsa Probar conexión. Revoca la API Key anterior una vez confirmada la nueva.

¿Qué hago si la API Key se compromete?

  1. Revoca la API Key de inmediato desde el perfil del usuario de servicio en TheHive ("My profile → API Key → Revoke").
  2. Revisa el registro de auditoría / logs de TheHive para identificar actividad del usuario de servicio en el periodo comprometido.
  3. Genera una nueva API Key y actualízala en el formulario del conector en Ruvic.

¿El usuario de servicio necesita ser administrador de TheHive?

No, y no debería serlo. Basta con un perfil acotado a manageCase, manageTask y manageObservable dentro de la organización de trabajo. Otorgar permisos de administración viola el principio de mínimo privilegio y amplía innecesariamente el impacto si la API Key se filtra.

Buenas prácticas Usa siempre un usuario de servicio dedicado y un perfil de mínimo privilegio; restringe el acceso de red por IP cuando sea posible; no compartas la API Key por canales no seguros; y confirma con el equipo de seguridad antes de automatizar la creación o el cierre masivo de casos.
